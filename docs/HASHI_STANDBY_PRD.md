## 1. 产品摘要

`/standby` 是独立于 `/call` 的“环境待命会话”：在用户明确授权的输入、时间、数据用途和动作范围内保持在场，默认安静；只有出现值得处理的事件，才记录、提醒、唤醒现有 HASHI Agent 或请求执行已授权的有限动作。

核心体验是**知道什么时候该介入，以及什么时候应继续安静**，不是持续对每句话回答，也不是另造一个 Agent Runtime。Fast Judge 是可替换、无工具、无自主循环的轻判断角色；复杂推理与工作交还 HASHI 原有 Agent、Engine 和 PAO 执行链。

必须同时具备两条职责独立的路径：**记录路径**按已确认的记录政策持续处理必要内容；**介入路径**按候选事件、Fast Judge 和代码政策决定是否行动。会议内容不能因为“不值得打扰用户”而被漏记；不需要记录的陪伴模式也不能因此被变成全天候文字档案。

首次使用先进入影子模式。影子不等于不采集、不外发或不收费：它只禁止主动业务行动；所使用的输入、模型、记录和预算仍需明确授权。

### 1.1 原创与复用的固定决定

HASHI 自行开发待命会话、目标解释、事件组织、介入规则、菜单、状态投影、权限和数据生命周期。**不嵌入、移植、套壳或依赖 Omi、Screenpipe、Frigate、Home Assistant Assist、LiveKit Agents 等同类产品／Agent 框架，也不以供应商主动音频会话替代此控制逻辑。**

优先复用 HASHI 已有 `/call` 媒体适配、语音与视觉处理、PAO 入队和取消、PCM 投影、隐私门禁、配置持久化、能力目录、计量与交付机制。只新增这些能力无法表达的最小契约。原创不要求重新训练每个 STT/TTS 模型，或重新实现操作系统媒体 API、TLS 和标准编解码；既有已批准依赖与配置模型可继续使用。新增依赖必须单独说明必要性、许可、隐私和隔离边界，不能借此引入另一套产品运行时。

## 2. 背景与问题

`/call` 面向主动通话；`/standby` 面向“Agent 在场，但大部分时间不行动”。目标场景保留：安静陪伴、会议记录、递纸条、休息／姿势提醒，以及实验性的婴儿辅助观察和访客接待。

持续调用完整 Agent 会带来不必要的成本、耗电、上下文污染和打扰；纯固定规则又难以理解自然语言条件。因此采用轻量感知、有限语义判断与原生 Agent 工作的分层设计，但权限、生命周期与资源上限始终由代码控制。

**实施顺序：**安静陪伴验证技术闭环；会议记录＋递纸条验证实际工作价值。健康、婴儿和访客模板不应迫使第一轮引入医学判断、身份识别或通用安防平台。

## 3. 产品目标

### 3.1 必须实现

- 用户用自然语言分别配置“观察什么”“发生时做什么”，并确认系统解释；一个 Profile 可含多个目标。
- 支持独立启停、影子／正式、暂停／恢复、到期、结束整理和删除；状态与真实能力一致。
- Fast Judge 可按原生能力目录更换；完整 Agent 只在明确、合规的升级后参与。
- 记录不依赖介入判定，采集不等待慢模型；所有缓冲、队列、重试和调用均有上限。
- 继承当前 `/privacy`，再叠加本会话更窄的采集、外发、保留、记忆和输出授权。
- 提供足以关联观察、判断、政策与结果的结构化证据，但默认不把内容复制进诊断日志。
- 普通交互继续使用 HASHI 的 Persona、语音、语言与会话；不制造竞争的聊天历史或权限系统。

### 3.2 成功标准

用户能解释系统为什么介入、为什么没有介入，以及哪些能力当前不可用。重点测量有用介入、误打扰、漏报、耗电／成本和隐私不变量；不以 Agent 被唤醒次数或模型调用次数作为成功指标。

隐私、权限、停止和重复执行属于确定性不变量，测试不得容忍越权“偶尔发生”。语义识别效果按模板、语言、输入质量和风险分别评测，不宣称全场景可靠。

## 4. 非目标与禁止事项

首发不取代医疗设备、婴儿监护器、安防／紧急报警系统；不做人脸身份、情绪诊断或执法判断；不自动解锁、购买、删除用户文件或对外代表用户作承诺。

不建设无限音视频档案、不默认录屏、不偷偷调用设备权限、不在后台用空白音频或高频轮询强行保活、不让配置文本成为任意代码。不新增常驻的通用 Agent 框架、第二套隐私等级、第二个权威会话库或供应商特定的业务控制流。

不承诺删除已发送给第三方的所有副本，也不把“本地文件已删除”描述为物理介质已安全擦除。桌面先完成可靠性验收；网页前台、移动端后台和锁屏分别声明实测能力，未验证的不承诺持续采集。

## 5. 核心概念与数据契约

### 5.1 Standby Session

PAO 所有的一段待命控制活动，绑定 owner、Agent、采集客户端／设备、实例和一个现有 HASHI Conversation Session。保存其 context generation、Profile revision、隐私／授权 revision、会话 epoch 和到期时间。它不是 Engine Session；不通过制造一个假 `/call` 来延长通话生命周期。

切换阅读视图不会重绑定待命。切换 Agent、实例或使原绑定失效时暂停并重新确认；不把旧上下文自动交给新对象。

### 5.2 Standby Profile

包含名称、多个目标及稳定 target ID、原始说明与已确认解释、必要／可选输入、观察窗口、记录政策、响应方式、资源范围、接收对象、工作时段、会话时长、Judge 选择、预算、冷却和数据保留。模型密钥、机器路径和真实参与者资料不得写进共享模板。

Profile 引用原生 STT/TTS/视觉／模型配置及其 revision，不复制第二份模型目录、语音设置或 `/privacy` 状态。运行时冻结可用配置；显示回退值不得被当成可写配置。冲突必须重新读取后由用户重做决定，不盲目覆盖。

### 5.3 Observation Episode

一个有界、有来源、有时效的观察对象，至少包含：

| 字段组 | 要求 |
|---|---|
| 身份与范围 | episode ID、source ID、owner／Agent／Session、epoch、相关目标 ID |
| 时间 | 采集起止、接收时间、时钟偏差／可信度、有效期；持续时间使用本地单调时钟 |
| 覆盖 | 哪些输入实际可用、缺失／丢帧／转写缺口；`observed`、`not_observed`、`unavailable`、`unknown` 分开 |
| 内容 | 有限转写／视觉描述／声音事件／计时事实；观察与推断分别标注 |
| 修订 | transcript segment ID、revision、interim／final、语言；新修订取代旧片段而非追加重复内容 |
| 证据与生命周期 | data ID／父数据引用、用途、敏感性、保存位置类别、expires_at、是否允许外发／回放 |
| 可重现性 | 感知、窗口、提示词、Judge、适配器和政策版本组成的 pipeline fingerprint |

没有信号不等于没有事件；摄像头断开不等于“持续无人进入”。单张图片不支持持续时长或跨帧变化断言。声音活动检测不等于哭声／警报分类；STT 没有文字不等于没有声音事件。

### 5.4 Fast Judge 与完整 Agent

Fast Judge 只做有限判断，无工具、记忆写入、浏览器、Shell 或自我重试循环。JEV 在当前 HASHI 中是 Agent Companion 实验，不是模型供应商，不复用其任务巡视生命周期作为环境判断器。

完整 Agent 复用原有 PAO Run 与 Engine。环境事件作为有来源、低信任的事件上下文进入，不冒充用户亲自输入的指令；直接呼叫后的已接纳语音轮次仍遵循现有语音确认与消息来源规则。

复用入队不等于自动沿用普通聊天的保存政策。要求临时不留存的 Profile 只能使用支持相同持久化、恢复上下文与清理契约的 Engine 路径；不支持时阻断升级并说明原因，不能悄悄把完整环境内容写入永久 Message。

## 6. 与 `/call`、`/phone` 的关系

| 项目 | `/call` | `/standby` |
|---|---|---|
| 主要预期 | 正在通话 | 在场、默认安静 |
| 启动 | 现有通话开场与连接反馈 | 不触发 Agent 开场、不播放通话铃音 |
| 输入 | 通话轮次 | 授权观察；仅选定事件成为工作 |
| 记录 | 现有通话语义与保留政策 | 独立声明的记录用途和保留期限 |
| 输出 | 当前通话的语音／字幕 | 私密提示、有限回应、笔记或经批准的动作 |
| 共用部分 | 媒体适配、语音呈现、PAO、PCM 等 | 引用同一原生能力，不复制实现 |

不得直接复用 `CallService.start()` 的完整业务流程：它会建立 Call、准备开场、维护通话轮次。应从既有实现暴露必要的公开原语，保留 `/call` 回归测试；不得访问另一服务的私有状态或复制整份 service 代码。

### 6.1 设备租约与共存

每个物理输入在 HASHI 控制范围内只有一个采集所有者；首发每个采集客户端／设备只有一个活动待命会话，跨 Agent 也不得争抢。同一会话的多个目标可以消费同一授权输入，不新增独立麦克风、转写或播放队列。

用户启动 `/call` 或 `/phone` 时，明确暂停该设备的待命，撤销待命输入与输出租约，再进入原通话；不把通话内容继续偷偷送给待命。通话结束后默认保持暂停。恢复必须用户可见且重新验证权限、绑定与到期；未来共享输入只有在原生租约明确支持且用户逐用途授权后才可开放。

关闭待命只释放其自身引用，不关闭其他合法消费者；不能控制其他应用时，界面只声明“HASHI 已停止采集”，不保证整个设备无人使用。媒体 track 的 mute、停止消费与真正释放是不同事件；必须验证释放而非只改图标。[B1]

### 6.2 唤醒后的对话窗口

正式模式下，明确呼叫成功后可进入短暂、可见的对话窗口：同一交谈中的追问不必每次重复名字，空闲超时后回到待命。建议空闲 30 秒，单窗口默认上限 5 分钟；持续对话应由用户明确转入 `/call`，不是偷偷扩展。

只复用 `/call` 当前的自然语音、FIFO、完整句流式、回声处理与打断原语。Agent/filler 的播放不能触发自身唤醒。打断只停止当前播放，不自动取消已有工作；显式停止任务仍走 PAO 取消规则。普通待命和递纸条检索不得播放等待 filler；只有已确认的交谈窗口才可使用既有短填充语，且不进入记忆、消息或会议原文。

## 7. 用户体验与 `/standby` 菜单

### 7.1 首页与持续状态

沿用 HASHI 命令卡片、共享导航、转义和界面语言，不另造 UI 框架。图形客户端沿用现有紧凑媒体面板及主题 token，不抢占整个聊天区、不新建右侧聊天档案。

```text
👁 STANDBY
──────────
状态：已暂停 · 影子模式
配置：安静陪伴
设备：当前电脑
输入：麦克风已停止 · 摄像头关闭
观察：明确呼叫或直接求助
处理：允许时唤醒 Agent，当前不执行
结束：22:00（设备时区）
隐私：继承 /privacy 1 · 原始媒体不保存
数据流：设备 → 此 HASHI 主机 → 已批准模型

[恢复影子测试] [查看试运行结果]
[观察与处理]   [输入与时段]
[允许的动作]   [隐私与数据]
[判断模型]     [模板]
[结束]        [↻ 刷新]
```

活动时始终可见：采集状态、模式、必要输入健康、记录开关、实际处理位置、到期时间、一键暂停／结束。控制台状态和传感器灯不能互相代替。摄像头预览可用与 Agent 获得可用视觉证据分别显示。

### 7.2 观察与动作配置

保存用户原文并显示简短解释、必要输入、范围、响应位置及当前不支持之处。“有人进入指定门口区域并停留”不自动解释为“识别陌生人”。“持续哭泣”必须说明所需声音识别能力；缺失时显示未支持，不能用普通 STT 伪装完成。

自然语言只描述目标，不能授权任意工具／路径／收件人。新增来源、扩大资源范围、启用外发、延长保留或改变接收者均需要可信控制界面确认。

### 7.3 输入与频率

麦克风、系统／会议音频、摄像头、定时事件分别选择。系统音频必须单独请求、展示是否真的取得；耳机下只采到本地麦克风时不得显示“完整会议记录”。默认摄像头关闭，屏幕采集不在首发范围。

界面分别配置事件触发、最短判断间隔、定时复查、无变化时长和行动冷却。冷却按目标与动作生效，不暂停记录或掩盖设备故障。纯定时提醒由原生 Scheduler 触发，不为读时钟调用模型。

工作档区分：节能呼叫、语义待命、视觉待命。未开启语义转写时，系统不得承诺理解所有不带名字的求助；用户能看到由此带来的能力与成本差异。

### 7.4 时段与模型

默认 2 小时，可选 30 分钟、8 小时、自定义及显式“直到手动停止”。后者仍需设备租约和资源上限，不提供无界队列／存储。工作时段引用原生 Scheduler 的时区与夏令时语义；时段开始不自动激活尚未授权的设备。

自动 Judge 只在**已配置、已通过资格验证、满足当前隐私与用途授权**的候选中选择，不用主 Agent 作为隐形回退。启用正式模式后冻结选定配置；关键 pipeline 改动重新校准，不在后台静默换模型。

### 7.5 用户可理解的结束操作

- **暂停**：立即停止本待命采集和未完成的介入，清空易失观察；已授权保存的笔记不删除。
- **结束**：停止采集、取消待命工作并终结会话；不偷偷再调用模型做会后总结。
- **结束并整理**：先停止采集，再执行单独授权、有时限的笔记整理；显示仍在处理，随时可取消。
- **删除本次数据**：独立的确认操作，列出将删除的范围、会保留的必要记录和第三方副本限制。

不为“暂停”弹出强制保存对话框而延迟停止。删除是本会话数据操作，不是删除原始 Workzone 文件，也不借 `/new`、`/fresh` 或 `/memory pause` 冒充清除。

## 8. Fast Judge 产品契约

### 8.1 能力与统一输入

适配器声明精确 provider／model／版本、输入模态、语言、结构化输出能力、上下文上限、超时、运行位置和原生隐私资格。普通模型“支持 JSON”不能自动视为已通过待命资格测试。

输入只包含目标说明、当前有界 Episode、必要的近期上下文、当前时间／冷却、允许动作枚举与证据有效期；不注入全部 PCM 或个人长期记忆。调用与重试均通过已有、经资格验证的模型边界，不能从 PAO 私下发 HTTP 绕过隐私过滤。

### 8.2 按目标返回结果

保留六种语义结果：`IGNORE`、`OBSERVE_MORE`、`RECORD_ONLY`、`WAKE_AGENT`、`BOUNDED_ACTION`、`UNCERTAIN`。一个 Episode 可含多个 target 结果，政策层合并兼容动作并解决冲突。

`RECORD_ONLY` 表示建议按现有记录政策标注事件，不授权新保存；会议基础记录也不等待此结果。`BOUNDED_ACTION` 只是已授权动作的建议，实际执行必须再经过代码门禁。

```json
{
  "schema_version": 1,
  "episode_id": "episode-example",
  "profile_revision": 4,
  "policy_revision": 9,
  "session_epoch": 2,
  "decisions": [
    {
      "target_id": "reference-help",
      "decision": "WAKE_AGENT",
      "reason_code": "possible_reference_need",
      "evidence_refs": ["segment-18:revision-2"],
      "requested_capability": "scoped_readonly_search",
      "valid_for_ms": 15000
    }
  ]
}
```

上述为待实现的契约示例，不是现有 API。ID、revision 和有效期必须由系统校验，不信任模型回填。未知字段／枚举、超长解释、非法资源及结构错误不得进入动作路径；示例中的短有效期不作为所有模板固定值。

### 8.3 控制规则

`OBSERVE_MORE` 只可要求已经授权的输入，建议最多追加 2 个片段、累计等待不超过 15 秒，并受更短的原始 TTL、场景时效和预算限制；不能自行开启摄像头或延长录音。

`UNCERTAIN` 默认不行动。只有明确配置的、有预算的低风险升级策略才可唤醒完整 Agent；模型故障、无效结果和隐私阻断不等于这种升级。超时最多按幂等请求策略进行有限重试，已外发请求状态不明时不并行投递多个供应商。

置信信息保留其来源；不同模型的自报分数不可直接比较。权限永不由置信度决定。结果提交前重新验证 epoch、输入修订、Profile、政策、权限与新鲜度，任何失败使结果失效。

## 9. 端到端流程与状态

### 9.1 独立记录、选择性介入

```text
可信用户设置 + 当前 /privacy + 原生能力资格
                         ↓
                授权检查与媒体租约
                         ↓
         本地采集／原生媒体处理／有界观察
                ↙                   ↘
记录路径：按记录政策         介入路径：候选 Episode
连续转写、缺口、修订             → Fast Judge
有授权才持久化                  → PAO 政策／预算／时效
                                → 原生 Agent 或有限动作
                                → 输出资格／接收者复核
                                → 原生送达与结果记录
```

两个路径是职责边界，不是两个服务集群、两个会话库或两份聊天档案。感知、转写与记录可以共享同一处理结果；候选合并不能删除需要保留的最终会议片段。

### 9.2 状态维度

| 维度 | 状态 |
|---|---|
| 生命周期 | `CONFIGURED / ACTIVE / PAUSED / FINISHING / STOPPED / EXPIRED` |
| 运行模式 | `SHADOW / ARMED` |
| 总体与逐目标健康 | `OK / DEGRADED / BLOCKED`，附必要输入状态 |
| 单个 Episode | `QUEUED / JUDGING / ROUTED / COMPLETED / REJECTED / CANCELLED / EXPIRED` |
| 交付 | `NOT_REQUESTED / QUEUED / SENT / ACKNOWLEDGED / FAILED / OUTCOME_UNKNOWN` |
| 数据处置 | `LIVE / EXPIRED / ACCESS_REVOKED / PURGE_PENDING / PURGED_LOCAL / EXTERNAL_UNCONFIRMED` |

模式、健康与单个模型请求不能覆盖生命周期。`FINISHING` 没有采集租约，只允许那次明确授权的整理任务。读取、刷新菜单和恢复客户端都不得把终态改回 ACTIVE。

### 9.3 版本屏障与取消

每次暂停、结束、授权撤回或绑定变化先推进 epoch／撤销令牌，再取消本会话任务和释放媒体。所有迟到的转写、Judge、TTS、视觉、工具和送达回调必须验证新的屏障；已撤回内容不能重新写回。

取消只针对带有本 standby ID 的 Runs／任务，不能用 Agent-wide stop 误伤用户其他工作；用户主动执行原有 `/stop` 时，遵守现有 Agent-wide stop fence，待命不得重新排入旧任务。明确保留的周期定义也不能擅自重开已停止的设备。

命令结果丢失时以原生请求 ID 查询，不能换入口重发未知状态的写操作。外部效果已提交但送达不明时显示 `OUTCOME_UNKNOWN`，不承诺恰好一次，不盲目自动重试。

## 10. 影子模式与评测

影子模式允许经授权的采集、感知、Judge、内容最小化诊断及已明确选择的记录路径；不启动业务工具、完整 Agent 检索、主动发言、外部通知或音乐。记录器自身的授权存储不被误解为业务工具动作。

运行故障必须显示，但提示不包含观察内容；必要故障通知走独立、预先授权的健康通道，不能借“影子”隐藏设备已失效，也不能借“健康通知”偷偷向第三方发送内容。

不能只用候选事件日志测漏报：使用可控的目标事件测试、已同意的非触发窗口抽样，以及人工标注；未授权回放就只保留统计并说明无法事后回看。分别评估感知候选、Judge、政策路由和真实送达。

影子结果只能证明“本来会不会行动”，不证明文件可检索或通知能送达；后者用隔离测试与受控正式测试验证。模型回放不得突破原样本用途、保留期限或当前 `/privacy`，每个外部目标都需单独资格。

首次启用及关键模型、STT、视觉、目标、阈值、窗口或动作扩权后回到影子，并由用户确认再 ARMED。仅收紧权限应立即生效，不以重新校准拖延撤权；安全文字或主题颜色变化不必触发模型重校准。有效期仍在的同一配置恢复暂停不强制重跑全部测试。

## 11. 日志、内容记录与证据

### 11.1 两类数据，不以“日志”混淆

**运行证据**默认保存事件 ID、相对／必要时间、版本、输入健康、判定枚举与原因码、政策结果、用量、Run／交付／删除状态。默认不保存转写、图像描述、提示词、Judge 自由文本、原始结果、文件名、收件人地址或完整模型请求。

**内容记录**包括转写、会议笔记、视觉／声音摘要、详细 Judge 依据、回放样本和回答。这些都可能含敏感数据，必须遵守第 12 节的明确用途、访问与保留规则；摘要不等于匿名。详细调试必须单独开启并自动到期，`/debug` 或 `/verbose` 本身不能取得内容采集许可。[B2]

既有 Events、诊断 journal 与 `/meter` 分工复用；引用同一事件／artifact，不复制原文到多个表或客户端。没有保留内容时，“为什么没有行动”只能显示结构化依据与内容已过期，不补造证据。

### 11.2 证据完整性

区分观察到的事实、模型推断、系统政策与实际结果。摄像头收到帧、视觉模型完成、消息已保存、消息已送达、用户已确认是不同证据。

匿名统计不得包含可反推人物或文本的裸内容哈希；需要去重时使用有界、会话限定的摘要标识。敏感内容不得进入 URL、异常堆栈、遥测、崩溃附件或共享缓存。诊断导出默认内容最小化；包含内容的导出需再次确认目的地与期限。

## 12. `/privacy`、安全与全生命周期数据治理

### 12.1 继承原生隐私，不重定义等级

以下是本次核对的当前基线，而非新建的待命等级，详见附录 A：

| 原生设置 | 已核对语义 | `/standby` 要求 |
|---|---|---|
| Level 0 | 隐私过滤关闭 | 不等于允许无授权采集、永久保存或任意外发 |
| Level 1 | 默认；信任所选供应商，无本地 PII 过滤 | 所有阶段仍需会话用途和目的地授权；清楚显示外发 |
| Level 2 | 本地 PII 检测后进行合格 HERV3／官方 DeepSeek 文本请求；需接受残余漏检风险 | 复用相同资格与出站门禁；不支持的调用直接阻断，不降级 |
| Levels 3–5 | 当前计划中、不可选 | 不在待命菜单假装可用，也不把“本地主机处理”命名为这些等级 |

当前 `/call` 的云端 STT、TTS、视觉在隐私等级不是 0／1 时被阻断；原生 Level 2 试点不授权直接临时模型调用或未经检查的媒体。**配置了 DeepSeek、把音频转成文字、或复用了某个适配器，都不自动使 Standby Judge 合格。**

首发必须继承这些阻断。Level 2 下的 Standby Judge／笔记整理，只能在原生隐私 owner 提供并验收有界、无工具或相应受控的出站入口后开放；否则明确显示不可用。已有本地 STT/TTS 能力可作为候选，但仍需全链路资格测试，不能以一个 `local=true` 标记认定不会外发。不得把判定拆到一个低隐私影子 Agent 来规避设置。

### 12.2 有效授权是交集

```text
有效权限 = 原生 Agent 权限
         ∩ 当前 /privacy 与部署政策
         ∩ 用户确认的 Standby Profile 用途／输入／动作／接收者
         ∩ 当前会话、事件、Workzone 与设备租约范围
```

Profile 可收紧但不能放宽原生政策；缺失、过时或无法取得当前政策时，受影响采集／处理／外发不得继续。读取设置走当前原生 owner，不扫描另一份 JSON 或复制 `privacy_level` 写入 Standby 数据库。保存 revision／当时的决策证据不构成第二个设置 owner。

传感器授权、处理授权、持久化授权、记忆授权、导出／发送授权相互独立。环境声音、访客回答、图像文字和检索文档始终是非可信数据，不能修改 Profile、降低 `/privacy` 或授权新接收者；明确呼叫也不是身份认证。[B3]

### 12.3 数据究竟到哪里

界面至少区分：**采集设备**、**HASHI 主机**、**外部处理服务**和**交付目的地**。“模型运行在 HASHI 主机本地”不等于“数据未离开手机”；VPS 也不是用户设备本地。

逐阶段展示 STT、视觉、Judge、完整 Agent、TTS、检索、通知与诊断的目的地。可设置更严格的“禁止发送至外部服务”，但它只是本会话的收窄约束，不是新隐私等级；禁止时，云端搜索、TTS、推送、诊断上传也必须受控。采集设备到远端 HASHI 主机仍需单独可见授权。

地址与凭据取自可信实例配置，不接受模型、网页或未验证客户端指定的任意上传地址；采用现有认证、加密传输和资源边界。重定向、代理和 local 服务的下游外发都属于资格评估范围。

### 12.4 数据分类、默认保留与到期

以下数值是 v1.1 建议产品默认值，必须由一个原生配置 owner 定义并投影；不是已测性能或既有 `/call` 默认值。用户选择可在部署上限内收紧／调整，界面必须显示有效期限。

| 数据类别 | 默认处理 | 到期与删除要求 |
|---|---|---|
| 原始音频、摄像头帧 | 仅有界内存；持久化 OFF；分片与总缓冲最多覆盖 60 秒，受更短场景时效限制 | 消费完成尽快释放，最迟 TTL；暂停／停止／撤权清空；不得因模型慢而无限留存 |
| 当前观察、临时转写和滚动摘要 | 内存上下文默认至多 5 分钟且有 token／字节上限 | 不随 chat、checkpoint 或重启保存；暂停清空；缩短来源 TTL 时派生内容同步失效 |
| 会议完整转写 | 默认 OFF；启用前确认输入、用途、接收者和保留 | 开启时建议 7 天；缺口和修订可见，不能无限增量备份 |
| 会议笔记工作稿 | 仅在明确启用笔记时，允许受控存储并显示期限 | 默认结束后 24 小时供确认／保存；到期清除未提升工作稿 |
| 用户确认保存的笔记／交谈结果 | 显式提升至原生 Artifact／Conversation 持久记录 | 保存时显示目的地与该对象保留政策；“保留到主动删除”必须可见且明确接受，不受临时缓冲 TTL 暗中删除 |
| 运行证据（无内容） | ON，默认 7 天 | 最小化、访问受控；删除请求后仅保留声明必要的处置／安全凭据 |
| 详细诊断、原始媒体证据、评测回放 | OFF；分别授权，不因 Shadow 自动开启 | 开启时默认 24 小时，明确覆盖范围；TTL 到期同步清理缓存、索引及副本 |
| PCM 记忆／Memory+／Habit／远端记忆 | 从待命材料自动摄入 OFF | 用户明确选择内容与用途后才提升；原生 `/memory pause` 等继续生效 |
| 供应商保留与用户导出副本 | 不宣称受本地 TTL 控制 | 外发前披露已知政策／未知状态；删除结果逐处说明，不伪造远端证明 |

“原始媒体不保存”不保证无任何副本：操作系统交换区、供应商处理和用户导出有各自边界。实现必须禁用可控范围内的原文日志、自动崩溃内容、明文临时文件和默认内容备份；无法满足某个选定保护档时拒绝启用该档，并说明限制。

**自然到期与撤权删除不同。**原始媒体按短 TTL 正常淘汰，不自动删除另有明确用途和保留授权的转写／笔记；它们保留原始来源已到期的标记。用户撤回某数据用途或请求删除时，则按所选范围级联撤销派生内容；没有独立授权的派生物不得靠重新生成延长寿命。

“保存笔记”“保存完整转写”“保存原始录音”三个开关不得绑定。保存产物有独立 data ID、用途、原始 lineage 与期限；不得只复制到无管理的普通文件后仍称其可级联删除。

### 12.5 生命周期处置矩阵

| 事件 | 采集与新任务 | 易失数据／队列 | 已批准持久数据 |
|---|---|---|---|
| 配置／开始前 | 仅能力及政策检查；授权前不采集 | 不预先缓存环境内容 | 仅保存必要配置，不保存样本 |
| SHADOW／ARMED | 仅授权输入；按模式决定业务行动 | 有界处理与 TTL | 严格按所选记录政策，不因切正式扩大保留 |
| 暂停 | 先撤销采集与介入令牌，取消本会话在途工作 | 清空原始缓冲、临时上下文、待播放及待提交内容 | 保留此前合法保存的笔记／转写直到期限；不生成新总结 |
| 恢复 | 显式确认，重验政策、设备、绑定与到期 | 新 epoch、新鲜输入；不重放暂停期间事件 | 仅使用仍获授权的保留材料 |
| 结束／自动到期 | 终结采集与介入；到期不自动跑总结 | 清空并拒绝迟到回调 | 已保存产物保留；笔记工作稿按已显示的 24 小时规则；其他临时内容删除 |
| 结束并整理 | 先结束采集，仅允许该次有界整理 Run | 不再接收新媒体；取消后立即停止整理 | 仅对授权笔记材料处理，用户确认产物后提升保存 |
| 断线／设备锁定／前端冻结 | 未获持续采集资格的客户端本地即停；服务端租约过期后暂停 | 清空未提交片段，不缓存离线录音等重连外发 | 记下内容最小化的覆盖缺口，保留已保存部分 |
| Worker 替换／崩溃／应用重启 | 不自动恢复传感器，恢复为暂停 | 运行 generation 失效；新启动先执行 TTL／清理恢复 | 控制状态可恢复；不能从 checkpoint 重建临时原文 |
| `/privacy` 收紧／撤回用途 | 立即推进政策屏障；阻断不合格阶段 | 取消与清空不再允许的内容；迟到结果不得保存、发声或外发 | 分别按新政策处理；撤回某用途不等于静默删除用户正式文档 |
| `/privacy` 放宽／新增输入／换目的地 | 先可信界面确认；不自动启用或重放 | 新 epoch，只接收之后的新鲜输入 | 旧数据不得凭新授权自动回放；需要单独使用授权 |
| 删除本次数据／删除 Agent | 先停止关联活动、撤销读取与任务资格 | 清空所有受管缓存、输出与待发送内容 | 沿 lineage 删除范围内数据；显示本地、备份、外部各自结果，不删除无关 Workzone 原件 |

网络断开期间，客户端不能靠旧批准无限采集；使用短期能力租约及本地 watchdog。默认无离线补录和重连补传。移动端恢复前台并不等于用户同意重新录音。[B4]

### 12.6 删除、备份和“不能再记起来”

每份受管内容必须关联 `data_id / parent_ids / purpose / owner / expires_at`。删除先进行访问撤销和取消屏障，再调用原生数据 owner 清理原件、转写、摘要、搜索／向量索引、临时附件、TTS 缓存、客户端缓存和可管理副本。派生内容不能因来源被删除而变成无来源的永久记忆。

待命不自动进入 PCM、Memory+、Habit、远端记忆或训练集。用户选择保存／记住时，必须保留来源和撤回范围；既有后台整理也需识别这些排除标记。删除传入 Engine 的内容时，还要失效可能含该内容的 compact、恢复片段和可重建 provider context；在同一个逻辑会话内按原生机制重建干净上下文，不假装删除数据库一行就能让运行中的模型忘记。

对来源混合的摘要，先撤销受影响版本，再按剩余授权内容重建或删除；不得未经授权再调用模型来清理。实际无法追踪／失效的 Engine 路径不得开放“结束即删除”或“删除后不可再检索”的承诺。

删除任务应幂等、可恢复，返回逐数据 owner 的状态。持久队列只保留清理所需的最小 ID，不保存待删原文。读取在撤销生效后立即拒绝；物理清理尚未完成时显示 `PURGE_PENDING`，不能提前报成功。

常规备份默认排除原始缓冲、临时内容、回放和内容诊断。用户选择备份正式产物时，需显示备份保留与清理方式；恢复备份前先应用未过期的删除标记，防止复活。SQLite WAL、文件系统快照、SSD 和操作系统副本的物理清除限制应在技术设计中声明；加密与密钥生命周期复用可信原生／平台设施，不自制加密。

供应商没有删除接口、不能验证删除或存在保留期时，标记 `EXTERNAL_UNCONFIRMED` 并解释。已由用户下载或发到外部的副本不在 HASHI 单方面可控范围，删除界面必须单列；不写“全部彻底删除”。

### 12.7 逐边界检查与副作用控制

在采集授权、外发 STT／视觉、Judge 请求、Agent 升级、每次工具调用、持久化、TTS 和最终交付之前检查当前有效政策。排队时允许不代表提交时仍允许；收紧政策不能只等下个会话。

Level 2 的文本屏蔽复用原生过滤器，包含工具结果和后续请求；不得持久化原始值与占位符的映射。当前检测能力存在语言与 PII 漏检限制，过滤成功不等于匿名；不得把不同调用的占位符当成人物身份。

“只读文件”与“可以向房间里的人播报文件内容”分开授权。唤醒完整 Agent 后默认不继承它全部 Shell、文件、邮件或外部发送权限。检索仅使用 admission 时冻结的精确 Workzones 与允许的原生搜索范围，不扩大到共同父目录或全机扫描。

### 12.8 多人、敏感场景与合法使用

设备拥有者不自动有权记录所有参与者。开始前显示观察／记录范围、处理位置和可用的参与者通知；保留必要的确认事实而不是默认收集实名名单或声纹。参与者变化、转入敏感话题或提出停止时，提供立即暂停／删除入口，不靠 Judge 判断“应该不用同意”。

儿童、访客、客户和工作场景采用更严格的记录与输出默认值。具体司法辖区及机构要求需在实际部署前确认；本 PRD 是产品与工程要求，不构成法律合规认证。

## 13. 降级与故障行为

| 故障 | 默认处理 |
|---|---|
| Judge 超时／离线／输出错误 | 不执行；有界重试或显示受影响目标不可用；不切完整 Agent 兜底 |
| 必要输入缺失 | 目标 BLOCKED；其他独立且已授权目标可继续；“没有数据”不计为无事件 |
| 帧持续进入但视觉推理慢 | 分别显示采集正常、语义证据延迟；不靠提高帧率补救 |
| 记录路径过载／磁盘满 | 显示记录不完整，标记缺口；不能默默删除最终片段还声称完整 |
| 预算耗尽 | 阻断需预算的新处理；继续记录仅限另有授权与预算的路径；显示具体剩余能力 |
| 隐私状态未知／过滤器失败 | 阻断受影响处理；绝不发送未过滤内容 |
| 配置、授权或输入修订变化 | 拒绝旧结果；不重用旧动作；必要时回到影子 |
| Agent 忙／不可用 | 有界排队或丢弃过时介入；不新建隐藏 Agent 或复制运行时 |
| TTS／通知失败 | 展示实际失败；私密文字替代也需目标与通道授权 |
| 动作送达未知 | 保留未知状态，先查询；不得重发外部效果 |
| 清理失败 | 内容先不可读，后台按原生管理任务恢复清理；显示待清除范围 |
| 重启／长断线 | 默认暂停，不隐形恢复、不补发旧提醒 |

业务静默和运行健康提示分开。必要故障状态始终在本控制面可见；外部健康通知也受接收者、隐私和通知策略限制。无法提供必要可见降级反馈的客户端，不开放婴儿／访客等实验模板。

## 14. 专用模板

| 模板 | 输入与行为 | 特殊要求 |
|---|---|---|
| 安静陪伴 | 明确呼叫或合格语义求助；平时不回复 | 原始媒体与环境历史不保存；确认呼叫后才进入对话窗口；不把电视／引用语当身份 |
| 会议记录 | 授权音轨持续转写、记录议题／决定／行动项 | 记录不依赖 Judge；参与者告知；音轨覆盖和缺口可见；整理需结束并整理授权 |
| 递纸条 | Judge 判断是否值得检索；原生 Agent 限域查找 | 先检索再验证结果相关性与来源；查无可靠结果则安静结束；交付前再验时机 |
| 健康陪伴 | 计时提醒与姿势观察分别配置 | 计时用 Scheduler；姿势需时间序列及能力测试；不作诊断 |
| 婴儿辅助观察（实验） | 仅支持已验收的醒来／声音事件 | 不代替照护；不默认保存儿童媒体；健康故障可见；音乐音量、时长与通知对象预先限定 |
| 访客接待（实验） | 指定区域有人出现／停留 | 只问候或收集自述来意；不判定陌生人身份、不做人脸识别、不解锁；旁人文本不能改变权限 |

递纸条的正确顺序是：**可能需要资料 → 授权检索 → 来源与相关性核查 → 新鲜度及披露范围复核 → 提示或不提示**。唤醒 Agent 不意味着必须通知；迟到结果可在允许范围内进入静默待看区，而不是中断已结束的讨论。

模板共享契约，不强求完全相同的感知算法。模板未具备所需输入或评测证据时，界面标记实验／未支持，不用通用视觉摘要冒充专用可靠感知。

## 15. 功能归属、原生复用与修改边界

### 15.1 唯一 owner

PAO 拥有 Standby Profile／Session、epoch、目标政策、事件关联、预算预留、升级、取消与处置协调。PCM 只提供获准的 Persona／Context／Memory 投影，不持续监听、不授权；HERV3／其他合格 Engine 执行原生 Runs，保持 Engine Session 边界。Frontend Connectors 认证、采集、呈现和报告交付，不保存另一份权威会话。

原生隐私 owner 保留等级、资格与出站门禁。PAO 待命政策只叠加会话约束；数据由其已有 owner 删除，协调器不直接改所有模块的数据库。主要实现位于 Functions，不新增 Core 产品导入、全局监听线程或受保护 Core 状态。

### 15.2 已核对的复用入口

| 原生位置／契约 | 复用方式与必要修改 |
|---|---|
| `orchestrator/frontend_call/adapters.py` · `MediaAdapters` | 复用实例配置的 STT/TTS/视觉调用和凭据解析；调用前仍经当前隐私与用途门禁；不新增浏览器指定 URL 的旁路 |
| `orchestrator/frontend_call/service.py` | 参考／提取公开的有界协调、camera epoch、帧入口与推理新鲜度分离、TTS FIFO／缓存取消；不复制 Call 类、不制造假 Call |
| `orchestrator/frontend_call/ports.py` · `HashiPorts` | 复用 PAO 验证、有效隐私读取、Run 入队／取消、结果关联的原生边界；新增待命事件来源和更窄 scope，不冒充 call speech |
| `frontend_call/config.py`、`settings.py`、`transcription.py`、`billing.py`、`diagnostics.py` | 作为已存在的配置、转写、计量和诊断落点；具体扩展前检查其公开接口、保留政策与测试，不能假设均可无改动复用 |
| PAO Conversation／SessionStore／Events／attachments／交付契约 | 保持一个权威存储与原生 outbox／结果关联；观察内容默认不入普通 Message，仅显式交谈／保存产物进入相应原生 owner |
| `/privacy` 及 Level 2 出站资格 | 复用原生政策，不复制数字等级判断散落各处；新 Judge 路径先资格验证再启用 |
| 原生 Scheduler、`/bg`、取消与运行管理 | 定时、清理和需管理的后台任务通过原生入口；短媒体事件驱动处理不为每帧建立持久 Job |
| 原生配置持久化、命令元数据、能力／effort 目录 | 复用 revision-safe 写入、菜单生成与能力解析；不加第二套模型表或可写显示回退 |
| PCM 与原生记忆控制 | 只投影已授权内容；新增待命来源排除／显式提升／删除 lineage，不能默认长期学习环境内容 |

本次已读到当前 `/call` 声明 `batch_stt`，不得假定它已经提供持续会议流式转写。会议分片、重叠去重、最终修订与缺口记录是需实现并验收的 HASHI 原生扩展。当前视觉是单帧短描述；多帧持续事件也不属于已证实能力。

### 15.3 最小新增范围

新增一个有内聚边界的 PAO Standby 功能包，包含目标／Profile 契约、生命周期协调、Judge 规范化、记录与介入路由、处置协调和客户端协议投影。文件布局在技术设计时确定；这些是职责，不要求每项一个服务或数据库。

必要的共享原语在既有 owner 上小范围提取，`/call` 保持原行为。不要给巨型 Call service 叠加到处出现的 `if standby`；不要把所有媒体功能迁移到新通用框架。只有真实重用点才抽象。

**本 PRD 是 HASHI repo 交付。**外部图形客户端的采集／UI复用虽是后续实现依赖，本轮不修改其仓库、不创建其分支、不声称前端已完成。

## 16. 非功能要求

### 16.1 性能、成本与耗电

总预算覆盖感知、ASR、视觉、Judge、Agent、TTS、检索／通知、存储和传输；复用原生计量，避免把媒体费用与总费用重复相加。未知价格或用量显示未知，不按零估算。

按目标设置调用频率、并发上限与有限队列；建议每会话同时最多 1 个 Judge，等待候选合并／去重并设字节上限；慢 Judge 不阻塞采集。记录路径不能简单采用视觉路径的 latest-only 丢弃规则。开始有成本的调用前预留预算，完成后按证据结算；重试计费也纳入。

静音时尽量使用本地轻量事件检测，不持续请求网络模型；语义待命需要持续转写时必须显示其成本，不承诺“只有 Judge 命中才付费”。通过事件驱动、有限视觉帧和共享原生处理减少开销；不以提高帧率或反复初始化模型掩盖延迟。

在实际目标桌面上记录相对 idle 基线的 CPU、GPU、内存、网络、能耗与 8 小时稳定性；声明硬件／设置，不给没有测量依据的“低功耗”认证。

### 16.2 可靠性与平台

控制消息、采集帧、转写、事件和动作分别具有正确粒度的幂等 ID；传输重试不得制造重复笔记或重复提醒。源时钟不可信时使用接收时间与偏差界限，过期证据不因“刚处理完”而重新变新。

设备租约、UI可见状态、服务端 generation 与本地异步回调都需防陈旧结果。租约由服务端与客户端共同限制，进程暂停后恢复不能继续消费失效授权。原始缓冲和清理不依赖一次正常退出；异常恢复走原生清理任务。

首发验收以桌面为主。网页、Android、iOS、锁屏和后台按客户端能力声明；页面被冻结／丢弃的可能性不能用“服务器一直在线”掩盖。[B4]

### 16.3 国际化、可访问性与自然交互

沿用用户保存的界面语言；中、英、日分别评测，不用英语效果代替中文／日文。原始转写保持原语言；翻译另标注。提示简短、低打扰，默认不点评外貌或环境。

保留当前主题、字幕滚动与可触达控制；支持键盘／屏幕阅读器，不仅依赖颜色。查看记录时不强拉滚动位置；播放状态不再创建第二条字幕或聊天消息。

## 17. 实施与发布顺序

这是完整目标的分阶段施工，不以降低隐私／删除要求来换取一个不安全的 MVP。每阶段通过其门槛后再开放相应能力。

| 阶段 | 工作与交付 | 开放条件 |
|---|---|---|
| 0 · 契约冻结 | 原生复用差异表、有效隐私矩阵、数据清单／TTL、媒体租约、事件与Judge schema、评测夹具 | 未解决的资格／删除／取消缺口列为阻断项，不写成“以后再补” |
| 1 · 原生基础＋影子 | 菜单、控制状态、授权采集、有界观察、Judge、内容最小化日志、暂停／到期／删除；安静陪伴影子 | 未实现完整数据处置不得进入真实敏感使用 |
| 2 · 安静陪伴正式 | 原生 Agent 升级、短对话窗口、FIFO／回声与准确取消 | 权限收窄、停止屏障、隐私切换、单设备租约与实际音频验收 |
| 3 · 会议＋递纸条 | 连续记录分片／修订、显式保存、限域检索、来源核查、时机判断 | 完整覆盖／缺口证据、无授权外发测试、产物与派生数据删除测试 |
| 4 · 专用实验 | 计时与姿势分开；有限婴儿／访客模板 | 专门感知评测、明显降级、参与者通知和实验声明 |

每个实现提交仅改变清楚的一组边界，附 focused red/green 证据。共用媒体原语先保护原 `/call` 回归，再接待命；不批量重写 HERV3、Phone 或前端。技术实现后的 source、构建、Worker adoption 和物理设备验收分别记录。

| 模式／时长 | 首次 SHADOW；2 小时 |

| Judge | 原生目录中满足隐私资格的已配置候选；没有则 BLOCKED |
| 原始媒体 | 不持久化；内存上限与 TTL 均受第 12.4 节约束 |
| 环境转写／会议记录 | 临时观察不持久化；会议完整转写 OFF；笔记需明确启用 |
| 诊断 | 无内容运行证据 7 天；内容诊断／评测回放 OFF |
| 记忆 | 自动摄入 PCM长期记忆／Memory+／Habit／远端记忆 OFF |
| 主动输出 | 仅预先批准的当前私密端点；语音与外部通知逐项批准 |
| 并发 | 每采集客户端／设备一个活动待命；每输入一个采集 owner |
| 对话窗口 | 空闲 30 秒；默认单窗口上限 5 分钟，可确认调整 |
| 不确定／故障 | 不行动；故障状态可见；无静默模型／供应商回退 |
| 断线／重启／通话结束 | 待命暂停；不自动采集、不回放旧动作 |
| 清理／导出 | 默认无临时内容备份；导出再次确认；删除结果分本地／外部 |

Profile 模板不能覆盖更严格的原生隐私或部署上限。全部默认值只维护一处；表中的默认值是设计提案，实施时需建立对应的可验证配置与迁移。

## 20. 技术设计阶段必须关闭的事项

在实现相应能力之前，必须逐项形成决定和测试，不能用“理论可行”替代：

1. 原生 `/call` 可公开复用的媒体原语与回归边界；租约、长待命和短通话不能共用错误的时长假设。
2. Fast Judge 的实际调用路径、Level 2 资格与其他 `/privacy` 组合；未资格路线保持禁用。
3. 会议分片、说话来源、去重、修订、覆盖缺口和多语言能力；声音事件／多帧感知的独立限制。
4. 所有内容落点及删除 owner，包括 PAO、Engine、compact、附件、缓存、索引、PCM、备份与外部服务；缺失删除能力时哪些模式必须禁用。
5. 有界容量、TTL、预算预留、取消／送达未知与清理恢复；提供故障注入结果。
6. 各客户端的媒体权限、后台／锁屏与停止证明；外部前端的实施另行授权，不自动扩大仓库范围。
7. 模板评测集、质量门槛、参与者提示和敏感使用范围；不得把实验场景当无人值守安全保障。

技术设计需标明每项“原生已有／需小扩展／新增／仍未支持”。模型、感知组件和工程结构不在本 PRD 中凭空指定为已经可用。

## 21. 最终产品原则

**默认安静，介入有价值；记录与打扰分离；原创体验、原生复用；模型可换但权限不变；先影子、再行动；数据按目的存在、到期处置；停止是真的停止；不知道就明确显示不知道。**

让用户感受到的是一个合适时机才帮忙、知道边界的 HASHI Agent，而不是多了一台不停录制和自动说话的设备。
