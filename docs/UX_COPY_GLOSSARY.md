# HASHI 用户文案术语表（P1）

面向用户的中文界面、菜单、设置、报错统一使用本表。目标是让人一眼看懂“发生了什么、影响是什么、下一步做什么”。

## 写作原则

1. **先说结果**：发生了什么事，对当前任务有什么影响。
2. **再给下一步**：能做什么，不能做什么；不要只解释架构。
3. **不贴内部约束**：PR 说明、审计不变量、协议名、错误码留在日志或“技术详情”，不进主文案。
4. **一句话原则**：能一句说清就不用三句。免责声明不得超过正文。
5. **不用黑话**：优先“用户/助手/本机/版本/记录/检查/启用”，不用“代理契约/运行代/回执/投影/采用”。

| 内部词 | 用户文案 |

| adopt | 启用 / 更新（不用“采用”） |
| host / host machine | 本机 / 所在电脑（不用“母机”） |
| receipt | 确认 / 记录（不用“回执”） |
| generation | 版本 |
| projection | 同步结果 / 快照（不用“投影”） |
| qualification | 环境检查 |
| contract | 兼容要求 |
| hygiene | 完整性检查 |
| canonical | 当前 / 正式（不用“权威”） |
| surface | 界面 / 页面 |
| worker | 后台进程 |
| artifact | 文件 / 产物 |
| escalation | 升级处理 |
| runtime | 运行环境 |

## 各语言术语（agent）

每个界面语言只有一种写法，整套文案一起换，不在同一个界面里混用。

| 界面语言 | agent | 说明 |
|---|---|---|
| en / en-AU | agent / agents（标题大写 Agent） | 英文界面直接用 |
| zh-CN | 智能体 | 不用「代理」「智能工」；「代理」只留给网络代理 |
| zh-TW / zh-HK | 智慧體 | 不用「智能體」「智慧代理」 |
| ja | エージェント | 不写 Agent |
| ko | 에이전트 | 不写 Agent |
| de | Agent / Agenten | 德语本词，照用 |
| fr | agent / agents | 小写 |
| ru | агент / агенты | |
| ar | وكيل / وكلاء | |

配套固定说法：Agent Presence = 智能体在场 / 智慧體在場；Agent registry = 智能体列表 /
智慧體清單；Manage agents = 管理智能体 / 管理智慧體；Agent Connector、BotFather、
HASHI、Workbench、Telegram、WhatsApp 等产品名一律不翻译。

## 禁用词（用户界面）

采用、回执、投影、运行代、努力档位、母机文件、画布卫生检查、滞回控制、跨界通话、智能工、本地主权、后果性操作、安全失败、启用中的指针、开始办理、交办、L2 宣称、系统没有重试。

## 错误文案模板

```
❌ [发生了什么]：[可行动的原因]
[影响与下一步；最多两句]
```

示例：

- 不好：`⚠️ 上下文压缩安全失败`
- 好：`⚠️ 压缩未完成（原有对话未受影响）`
- 不好：`未执行重启；请先解决上述错误再采用，已完成的源码更新会保留。`
- 好：`更新未完成；当前版本未变。详细原因已写入日志。`

## 例外

- 安全/权限拒绝必须保留真实原因，但用用户能懂的话说明“为什么被拒、如何申请”。
- 技术详情可以折叠在“详情”里，但主文案不得直接出现英文异常、snake_case 错误码或内部枚举。
