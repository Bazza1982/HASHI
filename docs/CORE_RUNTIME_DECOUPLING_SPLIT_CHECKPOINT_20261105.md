# Core v5 original-dependency split checkpoint

Status: review-only source checkpoint. Full Gate 2/3, independent Core review,
release packaging and operator adoption are not accepted.

## Implemented boundary

Core starts from an independently qualified, zero-application-dependency
interpreter. Its release selector is anchored beside the installed role prefixes,
not accepted from an Agent, prompt, working directory, environment override or
CLI argument. External qualification records pin the full environment and
CPython base byte closures. Role-local policies preserve CR/FR identity when a
different source generation is qualified against the same immutable runtime.

The common private JSON launch owner serves shared Functions, Agent Workers,
qualification, candidate probes and recovery. A Windows venv redirector PID is
not an interpreter receipt. The actual OS image and parent relationship, Job
membership, selected runtime, one-time nonce and generation are checked before
the child receives permission to import product code. Prepared candidates are
retired on cutover cancellation before the cancellation is propagated; the
previous route and durable effects remain intact.

The platform reference builder copies only explicitly captured CPython and
approved Function package roots into a new destination. It checks the captured
inputs before and after materialization, builds distinct Core/Functions
interpreters without pip, writes role policies and full byte seals, and refuses
existing or nested Python environments. It never activates a release, installs
a service, updates an existing environment or restarts a Core.

The fixed selector and external record pins require an operator-controlled
installation authority. Formal installer ACL/LPAC protection of that authority,
an offline wheel supply chain and complete Portable/npm/Helm release integration
remain release gates. A fresh synthetic reference build is not a qualified
distributable installer.
